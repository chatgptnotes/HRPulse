## 2. Final Architecture

### Applications

| Service | Local URL | Responsibility |
|---|---|---|
| HRPulse backend | `http://localhost:3001` | HR database access, ESS APIs, leave decisions and payroll calculations |
| HRPulse frontend | `http://localhost:5173` | HR administration, including leave review and approval |
| Adamrit | `http://localhost:8080` | Hospital application and employee self-service HR screen |

All three services were listening at the end of the session.

### Request flow

1. The employee signs in to Adamrit using the Adamrit account/session.
2. Adamrit creates a signed, HTTP-only `adamrit_session` cookie.
3. The browser calls `/api/hrpulse-ess/...` on Adamrit.
4. The Adamrit relay verifies the session, adds the HRPulse integration token and employee email, and forwards the request to `/api/ess/...` on HRPulse.
5. HRPulse authenticates the integration and resolves the employee by email, employee number or external UUID.
6. HRPulse reads or writes the HRPulse Supabase project and returns only that employee's ESS data.

Production relay: `adamrit/api/hrpulse-ess/[...path].ts`  
Development relay: `hrpulseEssDevPlugin` in `adamrit/vite.config.ts`

## 4. HRPulse ESS API

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/profile` | Employee profile and shift details |

| `POST` | `/leaves/request` | Submit a leave request |

All ESS calls are integration-authenticated, employee-scoped and written to `ess_audit_logs` where applicable.

## 5. HR Leave Administration API

Mounted at `/api/leaves` in `backend/src/index.ts`.

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/leaves` | List and filter leave requests |
| `GET` | `/api/leaves/employee/:employeeId` | Employee requests and balances |
| `PUT` | `/api/leaves/balances/:employeeId` | Configure a leave balance |
| `PATCH` | `/api/leaves/:id/decision` | Approve or reject a pending request |

Approval behavior:

- Validates that a matching balance exists for the leave type and request year.
- Rejects approval when the available balance is insufficient.
- Changes request status only while it is still `pending`.
- Stores approver notes, decision maker and decision time.
- Moves leave days from pending to used and reduces available balance.
- Updates the employee's original submission notification to the final decision message.
- Leaves the decision successful if only notification delivery fails, while logging the notification failure.

## 8. Earlier Console Issues

### Multiple GoTrue clients

- Authentication remains on the primary Supabase client.
- Ordinary Adamrit data queries use a dedicated anon data client with session persistence disabled and its own storage key.
- This prevents OAuth session state from changing the role used by normal data-table requests.

### Anaesthetist count requests returning 400

- The count helper previously selected `id`, but the affected master tables do not contain an `id` column.
- It now performs `select('*', { count: 'exact', head: true })`.

### ESS requests returning 404

- The browser originally called `/api/hrpulse-ess/...` without a working development route.
- Vite now proxies these routes locally, while Vercel uses the catch-all serverless relay in production.

### Leave endpoints returning 503

- The required HRPulse tables were missing when the first requests were made.
- Migration `backend/supabase/migrations/20260722_ess_integration.sql` creates the ESS integration tables, indexes and constraints.
- The migration was applied to HRPulse project `lhqalhmlamdyjmeinozo`.

### Approved leave showing pending

- The request row was approved, but the historical submission notification still contained pending text.
- The decision flow no longer relies on a failing PostgREST upsert against a partial unique index.
- It finds and updates the submission notification, or inserts a decision notification when no submission row exists.

### React Router warnings

- `v7_startTransition` and `v7_relativeSplatPath` future flags are enabled on the active routers.

### PWA install message

- `beforeinstallprompt.preventDefault()` is intentional so the application can show its own Install control.
- The browser message is not an application failure.
