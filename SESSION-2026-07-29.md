## Rule Generator Validation

### Problem

The Rule Generator was creating fallback rules even when the prompt was unclear or unrelated.

Example problem:

- User types a command that is not an attendance/payroll rule.
- System silently creates a default late-coming rule.

### What Was Changed

Updated file:

- `frontend/src/pages/RulesPage.tsx`

### New Behavior

The Rule Generator now only supports attendance/payroll rule generation.

Supported rule areas:

- Late coming
- Absence
- Missing punch
- Missing swipe
- Early leaving
- Working hours
- Half day
- Overtime
- Shift

If the user enters an unsupported prompt, HRPulse now shows a message instead of opening the rule modal.

Message behavior:

- Clear info/error message appears below the Generate button.
- The message clears when the user edits the prompt.
- It does not create a wrong rule.

### Example Supported Prompt

```text
Late 3 times deduct 1 day.
```

### Example Unsupported Prompt

```text
Make a rule for hospital billing discount.
```

Result:

- HRPulse will not generate a rule.
- It will show that Rule Generator only supports attendance and payroll rules.

### Functionality Preserved

- Local fallback remains available for supported attendance/payroll prompts.
- Existing rule creation modal remains unchanged.

## Adamrit Uploaded Documents Opening in HRPulse

### Problem

Documents uploaded from Adamrit were visible in HRPulse Employee Master documents tab, but clicking them opened a blank HRPulse page.

Reason:

- HRPulse was using a raw frontend-relative file URL like:

```text
/uploads/documents/file-name.pdf
```

- The frontend dev server treated it like an internal app route.
- That caused a blank HRPulse page instead of opening the file.

### Backend Fix

Updated file:

- `backend/src/routes/employees.ts`

Added a secure admin download route:

```text
GET /api/employees/:id/documents/:documentId/download
```

This route:

- Finds the document for the selected employee.
- Checks the employee id.
- Sends the file from the backend upload folder.
- Sets `Content-Type`.
- Sets inline `Content-Disposition`.
- Returns 404 if the document is not found.

### Frontend Fix

Updated file:

- `frontend/src/components/employees/EmployeeProfileDrawer.tsx`

Changed document links from raw file URL to:

```text
/api/employees/{employeeId}/documents/{documentId}/download
```

### Result

Documents now open through the backend route instead of redirecting to a blank frontend page.
