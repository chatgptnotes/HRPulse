HRPulse and Adamrit Integration Report

Detailed explanation of the Employee Self-Service integration work completed on July 22, 2026.

Main idea: HRPulse remains the HR and payroll master system. Adamrit only displays employee-specific HR data through a secure portal.

1. Purpose

This report explains the integration work completed between HRPulse and Adamrit.

The goal was to keep both applications independent while allowing Adamrit employees to view their own HR information from HRPulse.

  • HRPulse remains the master system for HR, attendance, leave, payroll, salary, payslips, notifications, and HR business logic.
  • Adamrit remains the hospital management system.
  • Adamrit does not calculate salary, payroll, attendance, leave balance, deductions, or alerts.
  • Adamrit only displays employee-specific results that come from HRPulse.
  • The two databases were not merged.

2. High-Level Architecture

  1. An employee logs into Adamrit using the existing Adamrit login.
  2. Adamrit shows the Tablet View Dashboard.
  3. If the user has access to the HR tile, Adamrit shows the HR tile.
  4. The employee opens the HR tile.
  5. Adamrit shows a button: Load My HR Data.
  6. When the employee clicks the button, Adamrit prepares a secure server session.
  7. Adamrit server calls HRPulse server through a proxy.
  8. HRPulse verifies the integration token.
  9. HRPulse identifies the employee by a unique identifier, currently email by default.
  10. HRPulse returns only that employee's data.
  11. Adamrit displays the data in the Employee Self-Service portal.
The browser does not receive HRPulse service keys or Supabase service-role keys.

3. HRPulse Work Completed

3.1 New ESS API Route

A new HRPulse backend route was added at backend/src/routes/ess.ts and mounted in backend/src/index.ts.

The route is available under /api/ess. This is the HRPulse Employee Self-Service API layer that Adamrit consumes.

3.2 HRPulse ESS Endpoints

The new HRPulse route supports employee-scoped access for profile, attendance, salary, payslips, leave, notifications, alerts, and audit logging.

3.3 HRPulse Security

The HRPulse ESS API requires a server-to-server token named HRPULSE_ESS_TOKEN.

Adamrit must send this token from its backend only. It must not be exposed in Adamrit frontend code.

Supported employee identity headers include x-employee-email, x-employee-id, x-employee-number, x-employee-code, and x-employee-uuid.

The default matching method is email. Employee name is not used for matching.

3.4 HRPulse Business Logic Reuse

The integration reuses HRPulse's existing payroll and attendance services. Adamrit does not copy payroll formulas or attendance rules.

HRPulse produces gross salary, deductions, net salary, payable days, working days, late deductions, missing punch deductions, attendance percentage, and intelligent alerts.

3.5 HRPulse Database Migration

A new Supabase migration was added: backend/supabase/migrations/20260722_ess_integration.sql.

It adds leave balances, leave requests, HR notifications, ESS audit logs, and optional employees.external_uuid mapping.

4. Adamrit Work Completed

Adamrit was cloned inside the HRPulse workspace at C:\Users\hope4\hrpulse\HRPulse\adamrit.

4.1 New HR Tile

A new HR tile was added to Adamrit Tablet View. The module id is hr. The access-control tile id is t-hr.

4.2 HR Tile Access Control

The HR tile is now permission-based.

  • If a user has access to t-hr, the HR tile can appear.
  • If a user does not have access to t-hr, the HR tile is hidden.
  • If a user manually opens /hr without access, Adamrit redirects back to the tablet home page.

4.3 HR Employee Portal UI

A new HR portal screen was added at adamrit/src/tablet/modules/hr/HrEssFlow.tsx.

The page shows profile, attendance, salary, payslips, leave balance, leave requests, notifications, alerts, and attendance history.

4.4 Manual Load Button

The HR portal no longer loads data automatically. It first shows Load My HR Data. Only after clicking this button does Adamrit call HRPulse.

4.5 Adamrit Server Session API

A new Adamrit API route was added: adamrit/api/adamrit-session.ts.

It creates and clears a secure HTTP-only Adamrit session cookie used by the HRPulse proxy.

4.6 Adamrit HRPulse Proxy API

A new Adamrit API route was added: adamrit/api/hrpulse-ess/[...path].ts.

It verifies the Adamrit secure session, calls HRPulse with HRPULSE_ESS_TOKEN, and forwards only the logged-in employee's identity.

4.7 Local Dev Middleware

Vite local development does not automatically serve Vercel API functions. A dev-only middleware was added in adamrit/vite.config.ts to support /api/adamrit-session and /api/hrpulse-ess/* locally.

7. How To See The HR Portal

  1. Open http://localhost:8080.
  2. Log in to Adamrit.
  3. Open Tablet View.
  4. Make sure the user has access to tile t-hr.
  5. Click the HR tile.
  6. Click Load My HR Data.
  7. Adamrit will call HRPulse and show data if the Adamrit user is linked to an HRPulse employee.

8. Why Data May Not Appear

If the page says Adamrit secure session is missing, Adamrit frontend login exists but the backend secure cookie was not created.

If the page says HR profile is not linked, Adamrit successfully called HRPulse, but HRPulse could not find an employee matching the Adamrit user.

For example, if Adamrit is signed in as cmd@hopehospital.com, HRPulse employee master must contain the same email for data to appear.

9. Employee Mapping Rule

Current default: Adamrit user email maps to HRPulse employee email.

Supported future options: employee id, employee number, employee code, and external UUID.

Not allowed: employee name.

10. Leave Request Flow

  1. Employee submits leave request from Adamrit HR portal.
  2. Adamrit sends it to /api/hrpulse-ess/leaves/request.
  3. Adamrit proxy forwards it to HRPulse /api/ess/leaves/request.
  4. HRPulse stores it in leave_requests with status pending.
  5. HRPulse Super Admin approves or rejects it in HRPulse.
  6. Adamrit displays the updated status.

11. Notification And Alert Flow

HRPulse owns notifications and alerts. Adamrit displays them only.

Examples include missing punch reminders, late warnings, payroll processed messages, leave approval or rejection updates, holiday reminders, birthday wishes, work anniversary messages, company announcements, low attendance alerts, multiple missing punch alerts, and three consecutive late arrival alerts.

12. Security Notes

  • HRPulse service-role key is not exposed to Adamrit frontend.
  • Adamrit service-role key is not exposed to Adamrit frontend.
  • HRPulse ESS token is server-side only.
  • Adamrit browser calls only Adamrit local/proxy APIs.
  • HRPulse validates token and employee identity.
  • Employees cannot type another employee id into the HR UI.
Real secrets were pasted during the conversation. They should be treated as exposed and rotated in Supabase, OpenAI, Gemini, and DoubleTick dashboards.

15. Simple Explanation

HRPulse is the HR office. Adamrit is the hospital work app.

The new HR tile in Adamrit is like a window into HRPulse.

When the employee clicks Load My HR Data, Adamrit asks HRPulse: show me only this logged-in employee's HR data.

HRPulse checks the request and sends back only that employee's information. Adamrit displays it. Adamrit does not calculate or own the HR data.
